# 已知限制与后续开发建议

## 1. 文档目的

本文档明确当前版本的能力边界，避免把已实现的扫描、模型匹配、焊缝映射和几何轨迹执行误解为完整生产级焊接系统。当前版本没有焊接工艺控制、逆解预检和碰撞检查。

## 2. 当前已知限制

### 2.1 依赖路径不可移植

项目文件包含：

- `E:\Qt`；
- `E:\vcpkg-master`；
- `E:\PCL 1.15.1`；
- 残留 `Z:\vcpkg-master`。

Mv3dLp 与法奥 SDK 的头文件和导入库已收录在 `third_party/`，通过 `$(Mv3dLpRoot)` 和 `$(FairinoSdkRoot)` 相对引用，不再依赖绝对路径；但 `Mv3dLp.dll` 没有入库，也没有自动部署，运行时来源待确认。

影响：

- 新计算机不能直接编译；
- 依赖版本容易混用；
- CI 难以建立。

优先级：高。

建议：

- 统一 vcpkg manifest；
- 补充 `Mv3dLp.dll` 的部署目标；
- 使用环境变量或 MSBuild 属性；
- 删除机器特定 `.vcxproj.user` 交付依赖。

### 2.2 测试覆盖有限

当前自动测试覆盖：

- 请求版本；
- 相机采集状态；
- 焊缝刚性矩阵和坐标；
- 焊缝起点设定、方向反转、多链与闭合环；
- 扫描拼接（行序号补 Y、丢批补齐、轨迹模式、基坐标输出）；
- 位姿换算；
- 焊缝轨迹规划（含返回段）。

尚未自动覆盖：

- STEP 读取；
- PLY/PCD 读取；
- 预处理（含支撑平面单侧性判定）；
- 粗配准；
- ICP；
- 质量判定；
- VisualizationManager；
- UI 操作和菜单可用性；
- 相机真实帧解析；
- `RobotWorker` 与 `ScanController` 的状态机；
- `calibration.json` 解析。

优先级：高。

### 2.3 模型匹配测试数据在仓库外

当前测试 STEP/PLY 位于 `E:\document`。

影响：

- 接手人员无法从仓库复现；
- 文件可能被覆盖；
- 没有哈希和数据版本。

建议：

- 建立 `test-data` 独立包；
- 保存 README、来源、单位和哈希；
- 大文件使用 Git LFS、发布附件或内部对象存储；
- 不把敏感现场数据放入公开仓库。

### 2.4 只支持刚性且同尺度

算法只允许旋转和平移。

不支持：

- 缩放；
- 镜像；
- 剪切；
- 弹性形变；
- 焊接变形；
- 制造偏差补偿。

这是一项设计约束，不是简单增加 ICP 迭代即可解决。

### 2.5 残缺点云依赖可辨识结构

若扫描只保留：

- 单一平面；
- 圆柱对称面；
- 重复槽；
- 无孔无边的局部区域；

则几何上可能不存在唯一姿态。

程序会尽量通过特征和空间覆盖避免误判，并在日志中提示多解歧义，但歧义已不再阻断结果（见 2.11A），也不能创造不存在的信息。

### 2.6 自动工件聚类只选择一个主体

当前预处理只保留评分最高的聚类。

风险：

- 工件因遮挡分裂为多个连通区域；
- 主体被误选为夹具；
- 多个合理区域未共同参与匹配。

后续可保留前 K 个合理聚类，分别进入粗配准并统一评分。

### 2.7 PPF 计算与稳定性

PPF 点对特征规模大，因此限制 CAD 500 点、扫描 1400 点。

风险：

- 过度稀疏时小特征丢失；
- PPF 实现可能受法向方向影响；
- 异常仅记录并回退，不保证总能产生候选。

### 2.8 匹配任务不可取消

界面“取消操作”只取消焊缝选面，不取消模型匹配。

`QThread::quit()` 不能中断正在执行的 CPU 函数。

建议：

- Worker 使用原子取消标志；
- 每个长循环检查；
- PCL 黑盒调用前后检查；
- UI 增加“取消匹配”按钮；
- 明确取消后的结果作废。

### 2.9 相机与扫描参数硬编码

限制：

- 使用第一个设备（`m_preferredSerial` 成员存在，但没有界面）；
- 扫描参数写死在 `dianyun.cpp::onScanRequestAction()`：行程 200 mm、步距 96 µm、行率 600 Hz、曝光 80 µs、增益 0 dB、扫描速度 10%；
- 扫描位姿固定（Rx 180 / Ry 0 / Rz 90，基坐标 Z = 150 mm），没有界面可调；
- `MoveL` 的速度是百分比而非 mm/s，百分比与线速度的对应关系要现场标定；
- 没有设备选择或参数界面，没有配置持久化。

优先级：高，若进入现场使用。

### 2.10 标定与坐标链仍有残差

已完成：

- 法奥末端工具坐标 `hik`（X -0.065、Y -0.103、Z 250 mm，Rx/Ry/Rz 均为 0）；
- 线轮廓传感器标定（平均误差 0.291 mm、最大误差 0.844 mm）；
- 扫描时按行时间戳在 TCP 轨迹上插值，输出基坐标点云；
- 手眼外参在 2026-11-04 用两个已知焊缝起点做了平移修正（tx 42.52 / ty 88.47 / tz 41.82）。

仍然存在：

- 修正只用了两个样本，拟合残差约 ±3.7 mm；
- 约 3° 的偏航是否真实存在尚未确认，需补第三个已知点；
- 起点定位精度只有“可接受范围”的定性结论，没有量化指标；
- 斜装（rx -3.1° / rz 1.6°）使扫描行进方向偏离传感器 Y 轴约 3°，180 mm 行程约有 10 mm 横向漂移；
- `timeOffsetUs` 默认为 0，没有做正反向扫描标定；
- 相机到工装外参、工件到机器人基坐标的统一标定尚未建立；
- `HandEyeConfig.h` 编译期默认 `tz = 290.166` 未扣工具长，文件缺失时生成的模板不能直接使用。

详见 [标定记录](../calibration/README.md)。

### 2.11 焊缝只做刚性映射，轨迹只是几何轨迹

当前不会：

- 吸附到实际表面；
- 补偿制造误差；
- 穿越扫描缺失；
- 估计焊缝法向；
- 生成焊枪姿态（姿态固定为工具 Z 竖直向下）；
- 做逆解可达性预检；
- 做碰撞检查；
- 控制焊接电源、送丝或起弧/收弧。

软件现在可以把基坐标下的映射焊缝转成 TCP 轨迹并驱动机械臂执行，但它没有焊接工艺，也不检查可达性和碰撞，不可达点只能由控制器在对应段报错停机。首次执行新焊缝前必须先做“焊缝空走”。

### 2.11A 匹配判定不再有“人工确认”档

`MatchVerdict` 只剩 `Pass / Fail`。多解歧义、点到面 ICP 未收敛、覆盖率偏低只写日志，不再阻断焊缝映射和机械臂执行。

风险：对称工件、局部扫描可能得到“匹配通过”但姿态错误的结果，随后被映射并下发给机械臂。目前依赖操作员目视复核对齐 CAD 叠加效果。

建议：恢复一个可配置的“需要复核”档，或在歧义时要求显式确认后才允许执行。

### 2.11B 机械臂相关限制

- 只有 Release 配置启用机械臂 SDK，Debug 下为空实现；
- SDK 必须与控制器 web 版本对齐（现场为 v3.9.3.1，用 3.9.3 分支），控制器升级后需更换 SDK；
- 运动中途失败只停机，不自动返回；
- `RobotWorker` 的 IP 默认 `192.168.58.2`，没有界面修改；
- 部分相机/机械臂调用使用 `BlockingQueuedConnection`，worker 线程卡住时可能阻塞主线程；
- 没有硬件急停联锁，也没有用户权限控制。

### 2.12 没有结果导出

当前不能保存：

- `T_final`；
- 质量指标；
- 对齐点云；
- 焊缝点；
- 日志；
- 项目会话。

关闭程序后结果丢失。

### 2.13 日志未分级、未持久化

日志仅显示在 UI。

风险：

- 崩溃后日志丢失；
- 候选报告过长；
- 无统一问题追踪 ID；
- 难以统计性能。

### 2.14 可视化可能产生多个点云 actor

完整点云每 100000 点创建一个 actor。

大点云会产生较多 actor，可能增加：

- VTK 管理开销；
- GPU 内存；
- 交互延迟。

目前满足“显示全部点”的需求，但可进一步优化为单 actor 增量数据或 LOD。

### 2.15 参数基本为编译期固定

只有手眼标定 `calibration.json` 可在运行时修改并重新加载。其余参数（匹配、扫描、轨迹、相机）没有：

- 配置文件；
- 设置界面；
- 参数合法性报告；
- 参数版本。

算法调优和扫描参数调整需要重新编译。

### 2.16 Debug 和 Release 依赖配置不完全对称

Release 显式配置了更多 PCL 库路径、宏和 AVX。Debug 依赖较少，可能比 Release 更容易出现链接问题。

建议把共用配置移入 `.props`。

### 2.17 可维护性

`ModelMatchWorker.cpp` 仍较大，包含多个阶段。`dianyun.cpp` 在 7 月基线之后新增约 2000 行，承担了菜单构建、设备管理、扫描、轨迹执行等协调逻辑，也已偏大。

目前可读性尚可，但继续增加功能将导致：

- 编译慢；
- 难以单测；
- 阶段状态耦合；
- 调参影响不清晰。

建议把设备连接、扫描请求、轨迹执行从 `dianyun.cpp` 抽到独立的 Controller。

## 3. 后续开发路线

### 阶段 1：交付工程化

优先级最高。

1. 联网复核并同步本地提交到受控远程仓库；
2. 复核并持续维护现有 Visual Studio `.gitignore`；
3. 统一依赖路径；
4. 建立 vcpkg manifest 或依赖安装脚本；
5. 补充 Mv3dLp 运行库部署；
6. 将配置外部化；
7. 建立测试数据清单；
8. 添加 CI Release 编译和测试。

验收：

- 新计算机按文档一次配置成功；
- 无绝对路径修改也能构建，或只需修改一个配置文件；
- CI 自动输出测试结果。

### 阶段 2：算法可测试化

建议拆分：

```text
PointCloudPreprocessor
FeatureExtractor
CoarseRegistrationService
GuidedCropService
FineRegistrationService
MatchQualityEvaluator
```

每个阶段：

- 输入输出明确；
- 无 UI；
- 可保存中间结果；
- 有小型点云测试；
- 有失败用例。

### 阶段 3：结果持久化

新增：

- 配准结果 JSON；
- 4×4 矩阵；
- 所有质量指标；
- 输入文件哈希；
- 参数快照；
- 时间戳和版本；
- 焊缝 CSV/PLY/JSON；
- 可选对齐点云。

推荐结果结构：

```json
{
  "schema_version": 1,
  "software_commit": "c006de3",
  "cad_file": "...",
  "scan_file": "...",
  "units": "mm",
  "transform_direction": "cad_to_scan",
  "T_final": [],
  "metrics": {},
  "verdict": "Pass",
  "parameters": {}
}
```

### 阶段 4：相机产品化

1. 设备列表与选择（目前默认取第一台，仅有 `m_preferredSerial` 成员）；
2. 参数读取和写入界面（目前扫描参数写在 `dianyun.cpp` 中）；
3. 帧统计、丢帧和超时（已有基础统计日志）；
4. 将扫描速度百分比与线速度的标定结果固化；
5. 相机重连；
6. 录制原始帧用于离线回放测试；
7. 工位外参；
8. 补齐 Mv3dLp 运行时 DLL 的部署。

### 阶段 5：焊缝实际表面投影

建议保留两套数据：

- `rigidMappedSeam`：当前刚性基准；
- `surfaceAdjustedSeam`：扫描表面调整结果。

推荐算法约束：

1. 只在刚性焊缝附近半径内搜索；
2. 使用局部曲面法向；
3. 拒绝跳到相邻错误面；
4. 保持点序；
5. 对位移做平滑；
6. 对缺失区间保持 CAD 预测或标记无观测；
7. 输出每点置信度；
8. 不改变端点和长度时应显式说明；
9. 能回退到刚性结果。

### 阶段 6：焊接工艺与轨迹增强

当前已具备：基坐标下的几何轨迹（接近、下降、沿焊缝、退出、返回）和逐段 `MoveL` 执行。在焊缝表面调整稳定后，再增加：

- 切向；
- 两侧表面法向；
- 焊枪姿态（目前固定工具 Z 竖直向下）；
- 工作角和行走角；
- 焊接速度与工艺参数（目前只有百分比速度）；
- 起弧/收弧；
- 机器人逆解预检与可达性；
- 碰撞检查；
- 轨迹导出；
- 工位坐标转换。

## 4. 建议新增测试

### 算法单元测试

- 体素尺寸；
- 支撑平面单侧性判定与误删回退；
- 聚类选择；
- 空间覆盖；
- 候选去重；
- 刚性矩阵验证；
- 判定阈值边界。

### 合成配准测试

1. 从 CAD 点云生成局部扫描；
2. 应用已知刚性变换；
3. 添加噪声、离群点和遮挡；
4. 运行配准；
5. 比较估计矩阵与真值。

指标：

- 旋转误差；
- 平移误差；
- 通过率；
- 误通过率；
- 运行时间。

### 回归数据集

至少覆盖：

- 正常角度；
- 极端角度；
- 轻度/中度/重度缺失；
- 底板；
- 夹具；
- 定位环；
- 对称多解；
- 尺度错误；
- 非同一零件。

## 6. 禁止直接用于生产的情况

软件现在已经能驱动机械臂沿焊缝运动，但它是几何轨迹，不含焊接工艺。在以下条件未完成前，不应用于实际焊接生产：

- 未完成并复核手眼标定（`calibration.json`、`sensorAxis`、工具长扣除）；
- 未验证 CAD/扫描单位；
- 未目视复核对齐 CAD 的叠加效果（匹配 `Pass` 不再意味着已人工确认）；
- 未用“移动至焊缝起点上方”和“焊缝空走”核对新焊缝；
- 未建立矩阵和焊缝结果导出校验；
- 未进行焊缝表面调整或误差评估；
- 未生成焊枪姿态（目前姿态固定为工具 Z 竖直向下）；
- 未进行逆解可达性与碰撞检查（目前没有）；
- 未建立急停、权限和操作确认流程（扫描、移动、空走和沿焊缝执行前都有“是/否”确认对话框，默认“否”，但没有用户权限控制，也没有硬件急停联锁）；
- 未接入焊接电源、送丝和起弧/收弧控制。
