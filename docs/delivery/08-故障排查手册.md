# 故障排查手册

## 1. 排查原则

遇到问题时按以下顺序：

1. 保留错误截图和完整日志；
2. 记录 Git 提交、配置、输入文件和操作步骤；
3. 先判断是环境、输入、线程、算法还是显示问题；
4. 使用相同文件重复一次；
5. 不要在原因未知时同时修改多个阈值；
6. 修复后补充回归测试。

## 2. Visual Studio 项目显示“已卸载”

可能原因：

- Qt VS Tools 未安装；
- Qt 版本名称无法解析；
- `.vcxproj` XML 错误；
- 文件被重复加入多个项目；
- 依赖路径或导入文件不存在。

处理：

1. 右键项目，选择“重新加载项目”；
2. 阅读弹窗中的第一个具体错误；
3. 检查 Qt VS Tools；
4. 检查 `QtInstall` 名称；
5. 检查 `.vcxproj` 中同一文件是否既是 `ClInclude` 又被错误添加到其他项目；
6. 若提示文件属于两个项目，确认解决方案中没有重复引用。

## 3. 找不到 `qt.targets` 或 `qt.props`

现象：

```text
QtMsBuild: could not locate qt.targets, qt.props
```

处理：

1. 安装 Qt VS Tools；
2. 在 Qt Versions 中注册 Qt；
3. 确认版本名称为 `6.10.1_msvc2022_64`；
4. 检查用户属性表；
5. 清理 `.vs` 后重新打开解决方案；
6. 命令行构建时显式传入 `/p:QtInstall=...`。

## 4. 找不到 PCL/OpenCascade/VTK/Eigen 头文件

检查：

- `VcpkgRoot`；
- `x64-windows` 是否安装；
- `AdditionalIncludeDirectories`；
- 项目实际使用的是 `E:\vcpkg-master` 还是其他目录；
- 是否残留 `Z:\vcpkg-master` 路径。

不要同时混用不兼容版本的：

- PCL 头文件与库；
- VTK Debug 与 Release；
- 不同 MSVC 工具集生成的库。

## 5. 链接错误

### 找不到 `Mv3dLp.lib` 或 `fairino.lib`

检查：

```text
dianyun/third_party/mv3dlp/lib/Mv3dLp.lib
dianyun/third_party/fairino-3.9.3/lib/fairino.lib
```

以及项目属性：

```text
Mv3dLpRoot      = $(ProjectDir)..\third_party\mv3dlp
FairinoSdkRoot  = $(ProjectDir)..\third_party\fairino-3.9.3
AdditionalDependencies 含 Mv3dLp.lib（Release 另含 fairino.lib）
```

`fairino.lib` 只在 Release 配置链接；Debug 配置不定义 `DIANYUN_ROBOT_SDK`，`RobotWorker` 为空实现。库放在 `lib/` 而不是 `lib/Release/`，因为 `.gitignore` 的 `[Rr]elease/` 规则会排除后者。

### 法奥头文件导致 `errno_t` / `uint8_t` 重定义

`robot_types.h` 的 typedef 会与 CRT 冲突。厂商头文件只能出现在 `RobotWorker.cpp` 中；`RobotWorker.h` 通过 pimpl 隔离，`RobotTypes.h` 不得引用 SDK 类型。

### 大量 PCL/VTK 未解析符号

常见原因：

- x86/x64 不一致；
- Debug/Release 库混用；
- PCL 与 VTK 版本不匹配；
- vcpkg 与独立 PCL 安装混用；
- `PCL_NO_PRECOMPILE` 或点类型设置不一致。

## 6. 程序启动提示缺少 DLL

检查输出目录和 `PATH`：

- Qt DLL；
- `platforms\qwindows.dll`；
- PCL DLL；
- VTK DLL；
- OpenCascade DLL；
- `fairino.dll`（Release 构建后由 `DeployFairinoRuntime` 复制）；
- `Mv3dLp.dll`（来源待确认，仓库未收录，也没有自动部署目标）。

使用工具：

- Dependencies；
- Visual Studio Modules 窗口；
- `where Qt6Core.dll`；
- `where Mv3dLp.dll`。

避免把不同版本 DLL 随意复制到同一目录。若报 Qt 平台插件错误，见 27D 节。

## 7. STEP 导入失败

日志：

- STEP 文件读取失败；
- 文件中没有有效实体；
- 模型尺寸无效；
- 三角化或表面采样失败。

检查：

1. 文件扩展名和内容；
2. CAD 软件能否打开；
3. 模型是否只有无效引用或空装配；
4. 单位和坐标是否合理；
5. 文件路径是否包含无法被当前 OpenCascade 路径编码处理的字符；
6. 尝试导出为标准 AP214/AP242 STEP。

## 8. CAD 显示异常或选面错误

可能原因：

- 三角化精度过低；
- `cellToFaceMap` 与网格三角形数量不一致；
- actor 覆盖了拾取；
- 未按住 Ctrl；
- 点击的是空白区域。

检查：

1. 日志是否显示 CAD 导入成功；
2. 是否点击“新建焊缝”进入选面模式；
3. 是否按住 Ctrl；
4. 是否选择两个不同面；
5. 面高亮是否分别为红色和蓝色。

## 9. 点云导入卡顿

当前文件读取已在后台执行，但仍可能出现：

- 磁盘读取慢；
- PLY 解析耗时；
- 内存不足；
- 渐进显示期间 GPU/CPU 压力；
- 数百万点创建多个 VTK actor。

判断阶段：

- 状态“正在后台加载点云”：文件读取阶段；
- 状态“正在显示完整点云 XX%”：渲染阶段；
- 日志“完整点云显示完成”：已就绪。

处理：

1. 使用 Release x64；
2. 保证足够内存；
3. 使用 SSD；
4. 等待显示完成后再匹配；
5. 若只为算法测试，可后续增加“显示降采样/算法保留全量”选项；
6. 当前需求是显示全部点，不应直接删除原始点。

## 10. 点云颜色异常

原始点云使用 `z` 字段着色，不一定使用文件中的 RGB。

若颜色范围异常：

- 检查 Z 值单位；
- 检查是否存在极端 Z 离群值；
- 检查相机 `zScale`；
- 检查点云坐标轴方向。

## 11. “模型匹配”按钮不可用

必须同时满足：

- CAD 有效；
- 点云非空；
- 完整点云显示结束；
- 没有点云后台加载；
- 没有相机采集；
- 没有正在运行的模型匹配。

重点看状态栏是否仍显示点云渲染百分比。

## 12. 预处理后点数不足

日志：

```text
预处理后有效点数不足
```

可能原因：

- 原始点云太少；
- 体素过大；
- 底板剔除误删工件（见下文支撑平面日志）；
- SOR 过严；
- 聚类只选到小碎片；
- 法向估计产生大量无效法向；
- 单位异常导致邻域尺度不合理。

排查：

1. 记录原始点数；
2. 记录 CAD 对角线和 `leaf`；
3. 查看日志中的“平面候选 N”“剔除支撑平面”“工件聚类”行；
4. 检查聚类日志；
5. 不要直接把最低点数改为更小。

支撑平面日志的读法：

- “平面候选 N：X 点，高度 H，下方 a%，上方 b%”：下方应接近 0、上方应有物体才会被判为支撑面；
- “，判定为支撑面”：该候选通过单侧性检查；
- “未识别到支撑平面，保留全部点”：没有合格平面，不剔除；
- “疑似误删工件表面，已回退到未剔除平面的点云”：剔除后主体尺寸比过小，已自动回退；
- 若底板始终未被识别：检查 `MatchConfig::scanUpAxis` 是否与点云坐标系一致（传感器和基坐标本机均为 +Z）；倒装或侧装必须修改。

## 13. 工件聚类选错

特征：

- 显示的处理后点云是夹具或圆环；
- 尺寸比明显异常；
- 粗配准失败。

原因：

- 工件被分成多个不连通块；
- 夹具比工件点更多；
- 工件残缺后对角线小于 0.45 倍 CAD；
- 聚类距离太小；
- 底板未被剔除（`scanUpAxis` 方向不对，或底板上下方都有点）。

处理：

1. 检查 `ClusterTolerance = 2 * leaf`；
2. 检查支撑平面日志（见第 12 节），确认底板被剔除；
3. 增加候选聚类而不是只保留一个；
4. 后续可让多个合理聚类共同进入粗配准评分；
5. 使用 CAD 引导裁剪作为第二道筛选。

## 14. 粗配准无有效候选

日志：

```text
粗配准未生成有效候选
```

优先检查：

1. CAD 和点云是否同一零件；
2. 单位是否一致；
3. 处理后点云是否为工件；
4. CAD/扫描降采样点数是否至少 100；
5. 关键点是否至少 100；
6. 特征覆盖是否过低；
7. 是否存在镜像关系。

当前算法不匹配镜像。镜像矩阵会被明确拒绝。

调参顺序：

1. 增加 `sacRuns`；
2. 适当降低 `sacInlierFrac`；
3. 增加关键点比例；
4. 检查 PPF 是否抛异常；
5. 不要先降低最终质量门槛。

## 15. 所有候选在 ICP 复核后失败

日志：

```text
所有粗配准姿态在ICP复核后均无有效对应
```

可能原因：

- 粗姿态仍太差；
- CAD 引导裁剪在 6.0 倍体素阶段保留点不足；
- 候选对齐了夹具；
- 单位错误；
- 点云缺失太严重；
- 法向方向和几何不稳定。

检查自动裁剪候选日志中的：

- 保留点数；
- 保留比例；
- 扫描覆盖；
- 特征覆盖；
- 空间覆盖；
- CAD 支持。

## 16. 精配准卡死或耗时很长

当前最大候选为 6，每个候选执行三次点到点 ICP，最佳候选再执行点到面 ICP。

处理：

1. 使用 Release；
2. 确认 OpenMP 生效；
3. 增大体素；
4. 减少粗候选数或 ICP 迭代；
5. 检查扫描聚类是否仍包含大量无关点；
6. 增加阶段计时日志；
7. 不要在 UI 线程直接调用 Worker。

## 17. 精配准崩溃

当前版本已增加：

- 最低点数；
- 非有限值检查；
- LDLT 状态检查；
- 对角阻尼；
- 旋转和平移步长限制；
- 未知异常捕获；
- 最终刚性矩阵检查。

若仍崩溃：

1. 使用 Visual Studio 捕获第一机会异常；
2. 保留输入文件；
3. 记录崩溃堆栈；
4. 检查 PCL 内部断言；
5. 检查内存是否耗尽；
6. 检查是否使用了不匹配的 PCL/VTK DLL。

## 18. 匹配完成但视觉上对不上

不要只看 RMSE。检查：

- 是否只对齐一个大平面；
- 圆弧、孔、台阶、端面是否一致；
- 空间覆盖；
- 特征覆盖；
- CAD 支持；
- 是否存在对称多解；
- 点云是否实际包含另一个零件；
- `T_final` 是否被错误取逆。

视觉检查应至少从：

- 正面；
- 侧面；
- 顶部；
- 端面；
- 特征局部；

五类视角进行。

## 19. 匹配结果为“匹配质量不足”

判定只有“匹配通过”和“匹配质量不足”（`Fail`）两种，没有“需要人工确认”。

触发“匹配质量不足”的条件（任一）：

- 扫描覆盖 `< 0.30`；
- CAD 支持 `< 0.10`；
- 特征覆盖 `< 0.15`；
- 空间覆盖 `< 0.18`；
- 法向一致 `< 0.45`；
- RMSE 非有限或 `> 1.25 * leaf`；
- P95 残差 `> 2.0 * leaf`。

此状态下不显示对齐 CAD，焊缝映射按钮禁用，是预期行为。日志会输出诊断指标。

反过来需要注意：多解歧义、点到面 ICP 未收敛或发生回退、覆盖偏低（扫描覆盖 `< 0.55` 等）**不再阻断结果**，只在日志里提示，结果仍可能是“匹配通过”。对称工件出现“匹配通过”但姿态不对时：

1. 检查日志里的歧义提示和候选诊断；
2. 从多个角度检查对齐 CAD 的叠加效果；
3. 确认后再映射焊缝；绝不要在未复核的情况下驱动机械臂。

## 20. 焊缝创建失败

可能日志：

- 面相交计算失败；
- 两个面没有交线；
- 没有生成可用焊缝点。

检查：

1. 两个面是否真实相交；
2. 是否只是相邻但存在微小间隙；
3. 是否选择了同一面；
4. STEP 几何容差是否异常；
5. OpenCascade Section 是否生成 Edge。

对于存在间隙的设计，面求交不会自动推断焊缝，需要增加容差投影或边匹配算法。

## 21. 焊缝不明显

当前使用 VTK TubeFilter，而不是普通线宽。

管道半径：

```text
0.0025 * 模型显示尺度
```

可调整位置：

```text
VisualizationManager::showSeamTube()
```

调大后注意：

- 只影响显示，不应修改 `WeldSeamData` 几何；
- CAD 与点云视图应保持一致尺度；
- 过粗会遮挡模型边缘。

## 22. 点击焊缝列表后不同步高亮

检查：

- `currentItemChanged` 信号是否连接；
- 列表项 `Qt::UserRole` 是否保存正确 ID；
- CAD actor ID 是否为 `seam_tube_<id>`；
- 点云 actor ID 是否为 `mapped_seam_tube_<id>`；
- 映射焊缝是否已创建；
- Viewer 是否在主线程更新。

当前设计不需要分别点击两个视图。

## 23. 焊缝映射按钮不可用

必须满足：

- 选中列表项；
- 最新匹配 `success == true`；
- `verdict == Pass`；
- 没有加载、采集或匹配任务。

导入新 CAD 或点云后旧匹配失效，必须重新匹配。

注意：“焊缝映射”只需匹配 `Pass`，传感器坐标点云也可以映射并显示；但要让机械臂执行，还需要基坐标点云、已设起点，见 27C 节。

## 24. 映射焊缝离点云表面有偏差

原因可能是：

- 模型匹配误差；
- 相机标定误差；
- CAD 与实物制造偏差；
- 扫描缺失；
- 焊缝本身位于不可见区域；
- 当前算法仅做刚性映射，不吸附最近点。

不能简单把每个焊缝点独立吸附到最近扫描点，否则会：

- 跳到错误表面；
- 破坏连续性；
- 缩短或拉长焊缝；
- 在缺失区域产生断裂。

推荐后续使用带连续性、CAD 曲面和距离门槛的受约束投影。

## 25. 相机无法连接

检查：

1. 其他软件（如厂商取流工具）是否占用相机；
2. 驱动是否安装；
3. 网卡 IP 与相机是否同网段；
4. Mv3dLp 运行时 DLL 是否在 `PATH` 或 exe 同目录（仓库未收录该 DLL，见 [03 第 3.4 节](03-编译与使用指南.md)）；
5. “通信 → 设备信息”是否能枚举到设备；
6. 日志错误码；
7. 是否连接了多个设备（默认取第一台，可设置 `m_preferredSerial`）。

状态指示灯：灰闪表示连接中；连接失败时进入 `Fault`，指示灯变红。

## 26. 相机输出数据异常（Profile/ABC16）

当前设备在 `ImageMode = 4` 下返回 `Profile/ABC16`，每点 3 个 `int16`：A=X 编码值，B 恒为 0，C=Z 编码值，空点三分量同为 -32768。

症状与原因：

| 症状 | 可能原因 |
| --- | --- |
| 点云是垃圾数据 | 按 float32 解读了 `ABC16`；检查解码路径 |
| 点云稀疏或全空 | 曝光/增益不合适；`photosensitivity` 不是 4（自定义）时曝光写不进去 |
| 单位偏大或偏小 | `LSLProfileCoordXUnit/ZUnit` 回读失败；回调里的 `fXScale/fYScale/fZScale` 恒为 0，不可用 |
| 日志提示列数不一致，帧被拒收 | 参数中途被改动；检查 `rejectedFrames` |

处理：不要仅放宽检查；用真实帧建立测试数据。

## 27. 扫描点云尺度、方向或形状异常

扫描几何必须自洽：

```text
速度(mm/s) = 步距(µm) × 行率(Hz) / 1000
```

检查日志中的“采集统计”和等效步距复核：

| 症状 | 可能原因 | 处理 |
| --- | --- | --- |
| Y 向整体被拉伸或压缩 | 速度与 步距×行率 不一致；`MoveL` 的 `vel` 是百分比不是 mm/s | 看“等效步距”日志，据此标定 `scanVelPercent`；基坐标/轨迹模式已按实测轨迹插值，不再依赖该假设 |
| 点云成条纹，实收数据只占很小一段 | 帧号跳变被当成丢批补空行 | 实收行率已达设定行率 80% 时程序会自动取消补齐；仍异常则检查帧号语义 |
| 点云前端多出一段原地重复轮廓 | 启动加速段被记录 | 默认位移超过 0.5 mm 才开始记录；检查机器人是否真的动了 |
| 行程末端缺失 | 停流太早 | 到位后默认再收 300 ms；设备按批打包，最后一批可能还没到 |
| 左右镜像 | `sensorAxis` 的 X/Y 符号不对 | 用“点选点云 → 移到该点上方”核对；镜像时改为 `[[0,-1,0],[-1,0,0],[0,0,-1]]` |
| 点云整体偏离基坐标 Z（如偏低约 260 mm） | `calibration.json` 的 tz 没扣工具长 | tz = HiCalibrator 原始值 − 工具 Z（250 mm），见 `docs/calibration/README.md` |
| 点云平均 Z 高于扫描起点 TCP Z | `sensorAxis` 反了 | 修正 `sensorAxis`，重新加载手眼标定 |
| 正反向扫描结果不重合 | 相机行时刻与遥测时刻偏置 | 正反各扫一次，调 `timeOffsetUs` 到两次点云重合 |
| 扫描越长，横向漂移越大 | 斜装（rx -3.1° / rz 1.6°）使行进方向偏离传感器 Y 轴约 3° | 180 mm 行程约 10 mm 漂移；在标定里修正，或重新安装 |

## 27A. 机械臂无法连接或频繁掉线

检查：

1. 控制器 IP 是否为 `192.168.58.2`（`RobotWorker::m_ip`）；
2. 是否为 **Release** 构建。Debug 不定义 `DIANYUN_ROBOT_SDK`，`RobotWorker` 为空实现，日志提示“当前构建未启用机械臂 SDK（仅 Release 配置支持）”；
3. SDK 版本是否与控制器 web 版本对齐。现场为 v3.9.3.1，只能用 fairino-cpp-sdk 3.9.3 分支；
4. `fairino.dll` 是否在 exe 同目录（由 `DeployFairinoRuntime` 复制）；
5. 控制器的 20003、20004、8080 端口是否可达。

注意：

- `RPC()` 建立的是异步连接，IP 不可达时也返回 0，所以连接成功以“状态流帧序号开始推进”为准，最多等 3 秒；
- 连续 5 次轮询失败，或 20004 状态流停更超过 1 秒，判定链路故障；
- 换回 v1.x SDK（`cobotAPI.lib`）会导致 `MoveL` / `GetInverseKinRef` 参数个数不同，响应解析抛 C++ 异常，运动指令无法下发；
- 不要使用带 `FRCNDEClient` 的更新版本，它依赖 20005 端口。

故障码在机械臂状态里显示（主/子故障码）；“通信 → 清除报警”执行机械臂故障复位，界面“解除报警”只清除界面报警条。

## 27B. 扫描无法启动或中途失败

“开始扫描采集”不可用时检查：

- 相机和机械臂是否都在线（两个指示灯均为绿）；
- 是否有匹配或点云加载在运行；
- 点云是否仍在分批显示（日志“点云仍在分批显示，请稍候”）；
- 是否有扫描或轨迹在运行。

常见失败日志：

| 日志 | 含义 | 处理 |
| --- | --- | --- |
| 定位超时。 | 抬升或调姿态运动在 60 s 内未到位 | 检查机械臂状态、速度百分比、是否被限位或碰撞保护 |
| 相机起流超时，未收到任何轮廓数据。 | 起流后 2 s 内没有首帧 | 检查相机连接、激光和参数 |
| 扫描运动失败：… | `MoveL` 失败 | 看错误文本；常见为目标不可达、速度过高或控制器报警 |
| 扫描运动超时。 | 超过按行程推算的超时 | 检查速度百分比是否过低 |
| 扫描过程中相机断开 | 相机 `Disconnected` 或 `Fault` | 检查网线和供电；任何失败都会同时停机和停流 |
| 扫描未采集到任何轮廓数据。 | 一行都没记录 | 检查机器人是否真的发生位移（需超过 0.5 mm） |

扫描失败后确认激光已熄灭、机械臂已停止。

## 27C. 焊缝轨迹无法执行或执行失败

轨迹类菜单项不可用时，检查（全部要满足）：

- 点云为基坐标点云（用机械臂扫描得到；文件导入、单帧拍摄是传感器坐标，不能驱动机械臂）；
- `calibration.json` 有效（日志“手眼标定文件无效，请修正 calibration.json 后重新加载。”）；
- 机械臂在线且空闲；
- 已选中焊缝，最新匹配为 `Pass`；
- “移动至焊缝起点上方”还要求焊缝已设起点并已映射。

被软件拒绝的情形：

| 情形 | 原因 | 处理 |
| --- | --- | --- |
| 末端偏离竖直超过 30° | 自动调平上限；偏离更大多半是示教姿态与预期不符，自动转过去有撞件风险（扫描和轨迹共用该检查） | 先把机械臂手动调到接近竖直向下，再重新执行 |
| 焊缝最高点比当前 TCP 高出 100 mm 以上 | 视为点云或标定方向反了 | 核对 `sensorAxis`、tz 是否扣工具长、`T_final` 方向 |
| 焊缝有效长度过短 | 折线简化后少于 2 点 | 检查焊缝是否过短或映射失败 |
| 焊缝顶点包含无效坐标 | 映射结果含 NaN | 重新匹配并映射 |

执行中失败：

- 某段 `MoveL` 失败即停机，不自动返回；逆解不可达点只会在对应段由控制器报错，软件没有逆解预检；
- 起点位置偏差大：先用“移动至焊缝起点上方（30 mm）”目测，偏差超过 1~2 mm 时复核 `sensorAxis` 与外参，必要时补已知点复标；
- 首次执行新焊缝前，必须先“焊缝空走”核对路径；执行时现场人员须能随时触达急停，按 `Esc` 可停止轨迹。

## 27D. 启动报 “no Qt platform plugin could be initialized”

原因：工程链接 Qt 6.10.1，但 vcpkg 的 `applocal` 在构建后把 `E:\vcpkg-master` 下的 Qt 6.10.0 拷进输出目录，且不部署 Qt 插件，导致核心库与 `platforms/qwindows.dll` 小版本不一致。

处理：

1. 确认 Release 构建后执行了 `DeployQtRuntime`（`windeployqt --force`）；
2. 检查输出目录 `Qt6Core.dll` 等与 `platforms\qwindows.dll` 版本一致；
3. 手动重新部署时必须带 `--force`，否则 vcpkg 拷入的 DLL 时间戳更新，windeployqt 会判定为最新而跳过。
