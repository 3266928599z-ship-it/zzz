# 编译与使用指南

## 1. 适用范围

本文档说明如何在新的 Windows 开发环境中配置、编译、运行和操作 `dianyun`。

当前项目文件包含开发机绝对路径，不能保证复制到任意计算机后直接编译。首次迁移必须完成路径检查。

## 2. 当前已验证环境

| 组件 | 当前配置 |
| --- | --- |
| 操作系统 | Windows 10/11 x64 |
| Visual Studio | Visual Studio 2022 Community |
| MSVC 工具集 | v143 |
| Windows SDK | 10.0.26100.0 |
| C++ 标准 | C++17 |
| Qt | 6.10.1，MSVC 2022 x64 |
| Qt 模块 | Core、Gui、Widgets、OpenGL、OpenGLWidgets、Concurrent |
| PCL | 1.15.1 |
| VTK | 9.3 相关头文件与运行库 |
| OpenCascade | 通过 vcpkg include/lib 提供 |
| Eigen | 通过 vcpkg 提供 |
| 海康 SDK | MVS SDK，包含 `MvCameraControl.lib` |
| 架构 | x64 |

当前开发机路径：

```text
Qt:          E:\Qt\6.10.1\msvc2022_64
vcpkg:       E:\vcpkg-master
PCL:         E:\PCL 1.15.1
MVS SDK:     E:\MVS
解决方案:    E:\data document\dianyun\dianyun.sln
```

项目文件中还存在 `Z:\vcpkg-master\...` 库路径。迁移时应删除或改成实际路径，避免在其他计算机上产生误导。

## 3. 必需软件

### 3.1 Visual Studio 2022

安装工作负载：

- 使用 C++ 的桌面开发；
- Windows 10/11 SDK；
- MSVC v143 x64/x86 生成工具；
- C++ CMake 工具可选。

### 3.2 Qt 6.10.1

安装：

- Qt 6.10.1；
- MSVC 2022 64-bit；
- Qt VS Tools 扩展。

在 Visual Studio 中：

1. 打开 `扩展 -> 管理扩展`；
2. 安装 Qt Visual Studio Tools；
3. 打开 `扩展 -> Qt VS Tools -> Qt Versions`；
4. 添加 Qt 路径 `E:\Qt\6.10.1\msvc2022_64` 或新机器上的实际路径；
5. 名称应设置为项目引用的 `6.10.1_msvc2022_64`，或同步修改 `.vcxproj` 中的 `<QtInstall>`。

### 3.3 PCL、VTK、Eigen、OpenCascade

当前工程是混合依赖布局：

- 头文件主要来自 `E:\vcpkg-master\installed\x64-windows\include`；
- PCL Release 库路径来自 `E:\PCL 1.15.1`；
- Qt 来自独立 Qt 安装；
- MVS 来自独立 SDK。

迁移时有两种方案：

#### 方案 A：复现当前目录

优点：改动最少。

要求：

- 按当前路径安装或复制依赖；
- 保持版本一致；
- 检查所有 DLL 能被复制到输出目录。

#### 方案 B：统一使用 vcpkg

优点：长期更易维护。

要求：

- 使用同一 vcpkg 根目录；
- 安装 PCL、VTK、Eigen、OpenCascade；
- 移除项目中的多套 PCL/VTK 路径；
- 重新验证 ABI、Debug/Release 库和 Qt VTK 支持。

本次交付未完成依赖统一，建议迁移后单独建立一个依赖整理分支。

### 3.4 海康 MVS SDK

需要：

- 安装海康 MVS；
- 确认存在 `MvCameraControl.h`；
- 确认存在 `MvCameraControl.lib`；
- 将 MVS 运行时 DLL 放入系统 `PATH` 或程序输出目录；
- 确保相机驱动正常。

当前项目引用：

```text
Include: E:\MVS\Development\Includes
Lib:     E:\MVS\Development\Libraries\win64
Link:    MvCameraControl.lib
```

没有相机硬件时仍可编译，但必须提供头文件、导入库和运行时 DLL。若不需要相机，应通过编译开关隔离该模块，这是后续改进项。

## 4. 打开解决方案

1. 启动 Visual Studio 2022；
2. 选择“打开项目或解决方案”；
3. 打开：

```text
E:\data document\dianyun\dianyun.sln
```

4. 等待解决方案加载；
5. 若项目显示“已卸载”，右键项目并选择“重新加载项目”；
6. 若提示某个文件同时属于两个项目，检查 `.vcxproj` 是否重复添加或错误引用；
7. 确认解决方案包含：
   - `dianyun`；
   - `dianyun.tests`。

## 5. 配置检查

在编译前检查 `dianyun/dianyun/dianyun.vcxproj`：

### 5.1 平台

```text
Configuration: Release
Platform:      x64
Toolset:       v143
```

### 5.2 Qt

```xml
<QtInstall>6.10.1_msvc2022_64</QtInstall>
```

### 5.3 vcpkg

```xml
<VcpkgRoot>E:\vcpkg-master\</VcpkgRoot>
<VcpkgTriplet>x64-windows</VcpkgTriplet>
```

### 5.4 编译选项

Release 当前启用：

- `/std:c++17`；
- `/utf-8`；
- OpenMP；
- AVX；
- 多处理器编译；
- SDL 检查；
- 一致性模式。

### 5.5 宏

关键宏：

```text
PCL_NO_PRECOMPILE
BOOST_USE_WINDOWS_H
NOMINMAX
_CRT_SECURE_NO_WARNINGS
PCL_SILENCE_MALLOC_WARNING
```

## 6. 编译

### 6.1 Visual Studio 编译

1. 选择 `Release | x64`；
2. 右键解决方案，选择“重新生成解决方案”；
3. 确认输出窗口为：

```text
0 个错误
```

本次交付验证结果为：

```text
Release 主程序：0 个警告，0 个错误
```

### 6.2 命令行编译

在 Developer PowerShell 或已配置 MSBuild 的终端中：

```powershell
& "C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" `
  "E:\data document\dianyun\dianyun\dianyun.vcxproj" `
  /t:Build `
  /p:Configuration=Release `
  /p:Platform=x64 `
  /p:QtInstall="E:\Qt\6.10.1\msvc2022_64" `
  /m
```

测试工程：

```powershell
& "C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" `
  "E:\data document\dianyun\tests\dianyun.tests.vcxproj" `
  /t:Build `
  /p:Configuration=Release `
  /p:Platform=x64 `
  /m
```

## 7. 输出目录

主程序典型输出：

```text
E:\data document\dianyun\dianyun\x64\Release\dianyun.exe
```

测试程序典型输出：

```text
E:\data document\dianyun\tests\x64\Release\dianyun.tests.exe
```

运行前检查输出目录至少包含：

- Qt6Core.dll；
- Qt6Gui.dll；
- Qt6Widgets.dll；
- Qt6OpenGL.dll；
- Qt6OpenGLWidgets.dll；
- Qt6Concurrent.dll；
- PCL DLL；
- VTK DLL；
- OpenCascade DLL；
- MVS 运行时 DLL；
- Qt platform plugin，例如 `platforms\qwindows.dll`。

## 8. 运行测试

在包含 Qt DLL 的环境中运行：

```powershell
$env:Path = "E:\Qt\6.10.1\msvc2022_64\bin;" + $env:Path
& "E:\data document\dianyun\tests\x64\Release\dianyun.tests.exe"
```

预期输出：

```text

```

测试不需要相机。

## 9. 启动程序

方式一：在 Visual Studio 中将 `dianyun` 设为启动项目，按 `Ctrl+F5`。

方式二：运行输出目录中的 `dianyun.exe`。

启动成功后：

- 左侧 CAD 视图为深灰背景；
- 中间点云视图为黑色背景；
- 日志出现“系统已启动，操作日志就绪”。

## 10. 标准操作流程

### 10.1 只进行模型匹配

1. 点击“导入三维模型”；
2. 选择 STEP/STP；
3. 确认日志显示 CAD 采样点数；
4. 点击“导入点云模型”；
5. 选择 PLY/PCD；
6. 等待后台加载完成；
7. 等待状态栏显示“点云就绪”；
8. 点击“模型匹配”；
9. 等待预处理、粗配准、精配准和判定完成；
10. 查看状态和叠加结果。

### 10.2 使用相机点云

1. 连接相机并关闭可能占用设备的 MVS Viewer；
2. 点击“开始拍摄”；
3. 等待日志显示采集和拼装完成；
4. 等待完整点云显示完成；
5. 导入对应 CAD；
6. 点击“模型匹配”。

### 10.3 创建焊缝

1. 导入 CAD；
2. 点击“新建焊缝”；
3. 按住 `Ctrl` 单击第一个 CAD 面；
4. 按住 `Ctrl` 单击第二个不同 CAD 面；
5. 查看焊缝列表、长度和管道显示。

### 10.4 映射焊缝

1. 完成模型匹配；
2. 确认状态为“匹配通过”；
3. 在焊缝列表选择一条焊缝；
4. 点击“焊缝映射”；
5. 在点云视图查看映射管道；
6. 切换焊缝列表，确认两个视图同步高亮。

## 11. 如何理解结果

### 匹配通过

- 可显示对齐 CAD；
- 可执行焊缝映射；
- 仍建议从多个视角人工检查边缘、圆弧和端面。

### 需要人工确认

- 可显示对齐 CAD；
- 不允许焊缝映射；
- 检查是否为对称多解、局部重合或点到面 ICP 未收敛。

### 匹配质量不足

- 不显示对齐 CAD；
- 检查单位、工件、底板剔除、聚类、残缺程度和特征。

## 12. 清理与重新测试

无需清理即可重新导入。

行为：

- 导入新 CAD：清空焊缝、旧匹配和旧映射；
- 导入新点云：保留 CAD 焊缝，但清空旧匹配和旧映射；
- 删除焊缝：同步删除 CAD 和点云视图 actor；
- 匹配运行期间：导入与拍摄按钮禁用。

## 13. 迁移到新计算机的验收

迁移完成后依次验证：

1. 解决方案无卸载项目；
2. Release x64 编译成功；
3. 测试程序输出通过；
4. STEP 能导入；
5. PLY/PCD 能后台导入；
6. 点云全部显示；
7. 模型匹配能运行完成；
8. 焊缝能创建；
9. `Pass` 后焊缝能映射；
10. 有硬件时验证相机采集。
